# net 파트 기록 (rb-net, 11-19) — 멀티 버퍼링·끊김

> 사용자: "멀티 버그가 많다. 버퍼링이 너무 심하고 끊김도 심하다." v20(1a666bc)은 괜찮았음.
> 바꾼 곳 태그 `// [net]`. 서버 물리·판정은 안 바꿈(AI 9이닝 40경기 득점·안타·실책·공 궤적 해시가 ad4c38e 와 비트 단위로 같음).

## 측정 도구
```
node tools/qa/netbench.mjs [--client=v20|cur|new] [--root=/tmp/v20] [--players=4] [--sec=600] [--ping=120] [--jit=30] [--loss=0.01] [--fms=20 --fspike=0.03] [--seed=N] [--json]
node tools/qa/run.mjs multi --ping=120 --jit=30 --loss=0.01      # 브라우저 멀티(진짜 main.js)에도 같은 지연 주입 (room.mjs)
```
- 진짜 `Room`(src/index.js) + `Game` 을 **가상 시계**로 돌리고(600초 경기 ≈ 5초), 가짜 WebSocket 에 지연(핑/2)·지터(반정규 σ)·손실(TCP 라 재전송 `ping+100ms` + 뒤 메시지 순서 대기)을 넣는다. 봇 N명이 실제로 투구·스윙.
- 클라 모델 `tools/qa/netclient.mjs`: main.js 의 수신·보간·외삽·공 합류·화면 이동(place)을 그대로. `new` 는 main.js 가 쓰는 `client/net/interp.js`·`snap.js` 를 직접 불러 씀.
- `--fms` = 클라 프레임이 바쁜 시간(메시지는 프레임 끝난 뒤 처리 = 브라우저 이벤트 루프), `--fspike` = 40~80ms 긴 프레임 확률.
- 옛 버전 비교: `git archive 1a666bc src shared | tar -x -C /tmp/v20`, `git archive ad4c38e src shared | tar -x -C /tmp/cur0` → `--root=`.
- 항목: 내려받기 KB/s·스냅샷 바이트, 서버 루프 CPU(틱+스냅샷+직렬화+수신), 파싱 ms, 화면 지연(서버 시각 − 화면 시각), 언더런(보간 시각이 마지막 스냅샷 뒤)·멈춤(언더런 중 외삽 없이 정지), 끊김(진짜로 2m/s+ 움직이는데 화면은 30% 미만), 0.3m+ 점프, 공 위치 오차 p99·점프.

## 원인과 수정
| # | 원인 | 수정 (파일) |
|---|---|---|
| 1 | 보간 버퍼가 바닥나면(지터·손실) 선수가 그 자리에 **멈춤** → 다음 스냅샷에 한꺼번에 이동. 손실 1%면 프레임 6.5%가 멈춤. 앞당기기(1.5m)도 멈춘 동안 빠져 뒤로 튐 | 마지막 구간 속도로 최대 0.18초 외삽(`client/net/interp.js`) |
| 2 | 보간 지연 = 1/30 + 2.2×(도착 간격 차이 EMA) — 늦은 스냅샷 하나가 두 번 세지고 손실 한 번에 지연이 몇 초간 커짐(버퍼링 느낌) | 스냅샷마다 '늦음'(도착+시계차−서버시각)을 재서 최근 4초 90% 분위 + 간격 + 8ms. 지연은 재생 속도 0.85~1.2배 안에서만 바뀜 |
| 3 | 공 합류: 스냅샷이 프레임 사이에 오면 서버 공을 '지금'까지 굴려 '지난 프레임' 공에 합류 → 다음 프레임에 또 적분 → 공이 앞서 갔다 끌려옴(30fps 에서 0.3m+ 점프 178회/분, 오차 p99 2m) | 화면 공에 자기 시각 `tb`: 합류는 tb 기준, 프레임은 tb→지금 적분(`mergeBall`/`stepBall`). 스냅샷이 화면 공보다 '미래'면 짧게 되돌려 비교 |
| 4 | 서버 시계 추정: 더 빨리 온 스냅샷 하나에 시계를 바로 앞으로(수~수십 ms) → 공·투구 순간 이동 | 앞으로는 스냅샷당 최대 3ms 씩 |
| 5 | 스냅샷을 매번 통째로(1.5KB × 30Hz × 사람 수) | 지난 브로드캐스트와 달라진 키만(`src/index.js packSnap` ↔ `client/net/snap.js`), 3초마다·새 접속 때 통째로. 왕복 동일성 테스트 `tests/net.test.mjs` |
| 6 | 사람 수비수 이동을 20Hz 로 보냄 → 다른 사람 화면에선 30Hz 스냅샷 3개 중 1개는 제자리(계단 끊김) | 30Hz, cm 반올림. 서버 `onMove` 간격 하한 0.05→0.02초(30Hz 에서 전력질주가 조깅으로 잡히지 않게) |
| 7 | 모두 잠깐 끊겨 90초 보존 중인 방: `/api/room` 이 '없음' → 혼자 있던 사람이 새로고침하면 자기 자리로 못 돌아감 | 보존 중이면 있음 |
| 8 | 서버 시각이 크게 뒤로 가면(방이 새로 만들어짐) 옛 시각을 넘을 때까지 새 스냅샷을 다 버려 선수 멈춤 | 버퍼 비움 |
| 9 | 재접속 직후 옛 소켓에 남은 메시지가 새 소켓 것과 섞임 | 옛 소켓 메시지 무시 |

### 클라 프레임 (qa 요청 처리)
| 것 | 전 | 후 |
|---|---|---|
| 관중 웅성임·박수 버퍼 합성(첫 소리 켤 때 한 번) | 이 서버 50 + 85ms | 30 + 25ms (잡음 표 순서 읽기·곱셈 감쇠, 소리 성격 같음) |
| `_post()` IK·시선 때 `root.updateMatrixWorld(true)`(뼈 53개+장비) | 매 프레임(심판 look 상시) | 지움 — getWorldPosition 이 부모 사슬만 갱신 |
| 먼 선수·화면 밖 애니메이션 'N 프레임마다' | 30fps 면 15Hz·5Hz 로 끊김 | fps 에 맞춰 N 축소(초당 횟수 유지, 60fps 는 같음) |
| 미니맵 | 2프레임마다 바탕까지 다시 그림 + 점마다 배열 | 바탕 캔버스 캐시 |
| 낙구·수비 가이드 예측 `integrate` | 초당 수천 번 결과 객체 할당 | `integrate(b, dt, world, out)` 재사용(서버는 그대로) |
- 남은 것: `AnimationMixer._update`/`slerpFlat` 할당(three 내부)·렌더(GPU)는 이 서버(SwiftShader)로는 못 잼 — 맥 fps 는 사용자 확인. 첫 공수 교대 때 상대 팀 선수 처음 만들기(데칼 캔버스) 한 번 ~30ms.

## 사용자 확인 (맥, 친구들과)
- 오른쪽 위 핑·fps. 친구 화면에서 내 수비수(직접 조작) 움직임이 계단처럼 끊기지 않는지, 타구·송구 공이 앞뒤로 떨리지 않는지.
- 와이파이가 흔들릴 때: 전엔 선수들이 잠깐 멈췄다 한꺼번에 이동 → 지금은 계속 움직여야 함. 혼자 남은 방에서 새로고침 → 자기 자리 복귀.
