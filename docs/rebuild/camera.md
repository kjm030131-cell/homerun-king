# camera 파트 기록 (rb-cam, 11-22)

> 코드: `client/game/camera.js` (main.js 에서 옮김 — main.js 는 `createCamRig(camera, ctx)` + 매 프레임 `camRig.update()` 만, `// [cam]` 태그).
> 지킬 것: 할 일 없을 땐 고정 중계(휙휙 X) · 타구 순간 컷 + `deadzoneCam`(gameplay 5-A, 숫자 그대로) · 공 위치 미리보기 금지.

## 사용자 옵션
- 설정 > 화면: **시점 거리**(가까이·기본·멀리, 경기 중 `Z`로 순환) — 망원 시점은 화각 ×0.86/1/1.17, 3인칭·주자는 거리 ×0.78/1/1.28. **타자 시점 높이**(낮게·기본·높게). localStorage `hr_camDist`, `hr_batH`.
- 키: `V` 시점 전환(기존), `Z` 시점 거리, `X`(투수, 누르는 동안) 주자 보기. 기존 키와 겹침 없음. 조작법(H) 반영.

## 검증
- `node tools/qa/camshots.mjs --tag=after [--side] [--only=bat,pitch,field,run,speed]` → `tools/qa/.out/cam-<tag>-*.png` (게임이 고른 카메라 그대로, 주자·관전은 `window.__camRole` 로 역할만 바꿔 찍음).
- 타구 화면 공 속도 (`--only=speed`, 연습 모드 40타구, 실제 카메라 화면 이동 px ÷ 맞는 순간 카메라를 얼렸을 때 px):
  | 구간 | 전(2회) | 후(3회) | main 6875dd7 합친 뒤 |
  |---|---|---|---|
  | 0~0.3초 | 100.6% | 100.3~100.5% | 100.6% |
  | 0.3~0.8초 | 88~94% | 82~91% | 86% |
  | 0.8~2.4초 | 63~69% | 63~72% | 59% |
  타구 섞임에 따라 회차마다 흔들림(같은 범위). 0.3초 뒤 줄어드는 건 공이 데드존을 벗어나 고개를 돌리는 분량(설계대로). `deadzoneCam` 코드는 그대로 옮김.
- main 합친 뒤: 단위 테스트 63/63, `flows.mjs` 6개 문제 없음, `run.mjs game-real game-pitcher game-cf practice derby --sec=60` + `multi --sec=40` 예외 0 (하네스 화면 공 보이는 속도 중앙 0.99~1.0).
- 성능: 새 할당 없음(smoothDamp 축 배열 제거), 매 프레임 타자 메시 traverse·주심/포수 visible 대입 제거(바뀔 때만).
