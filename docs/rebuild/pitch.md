# 투구 가독성·물리 (rb-pitch, 11-19)

> 사용자: "AI랑 할 땐 할 만한데 친구랑 1대1 하면 공이 어디로 오는지, 볼인지 스트라이크인지 구분이 안 된다. 공 오는 곳 미리 보여주는 건 아님. 현실성으로 고쳐봐."
> 공 위치 미리보기·예측 표시는 하나도 넣지 않았다(HANDOFF 0-3). 지나간 **뒤** 통과 지점 색만 바꿈.

## 1. 원인 — 사람 투수 vs CPU 투수 (숫자)
| | CPU 투수(보통) | 사람 투수(전) | 실제 MLB |
|---|---|---|---|
| 제구 오차 σ(축마다) | 6cm + 목표가 존 안 무작위 | **1.3cm(퍼펙트)·1.8cm(보통)** | 최고 제구도 평균 7인치(18cm) 빗나감 ≈ σ 14cm |
| 포심 구속 | 143 (D.speed 0.97, 게이지 0.78~0.96) | 149 (퍼펙트 0.84~0.97) | |
| 변화량 | ×0.98 | ×1.07 (퍼펙트 ×1.08) | |
| 실투 | 없음(대신 목표가 무작위) | 없음 | 가운데 몰린 공·행잉 변화구 |
| 릴리스 포인트 | 고정(RELEASE) | 같음 | |
| 투구 간격 | 1.4~2.3초(+첫 공 2초) | **0초(퀵 피치)~15초** | 타자 준비 전 투구 금지 |

사람 흉내(코너·경계 노리기, 퍼펙트 게이지 85%, 2스트 유인구) vs 보통 사람 타자(지각 모델, `tests/pitching.test.mjs`) 리얼 9이닝 12경기×2:
존 경계 ±5cm 공 **72.6%**(CPU 17%), 존 비율 68%, 볼넷 **0.3%**, 삼진 32%, 타율 .227, 존 밖 스윙 41%, 투구/타석 2.6.
→ 핀포인트로 경계만 찌르니 타자가 '골라낼' 방법이 없음(볼넷이 없어 다 쳐야 함) = 사용자가 말한 "볼/스트 구분 안 됨".

결과 (같은 흉내, 12경기×3 시드): 존 경계 ±5cm **72.6% → 31%**, 존 비율 68 → 50.5%(MLB 48~50), 볼넷 **0.3 → 7.5~9.4%**, 삼진 **32 → 21~22%**, 타율 **.227 → .256~.268**, 존 밖 스윙 41 → 21%, 투구/타석 2.6 → 3.0, 실측 σ 14cm.
같은 타자가 CPU 투수 상대: 타율 .26~.27 · 삼진 22~24% · 볼넷 4~6%.

### 공 보이기(클라, 위치 정보 없음)
- `client/game/batting.js` 옆 `client/game/ball.js`: 공에 실밥 텍스처 + **구종별 회전축**(포심 백스핀, 투심 기운 백스핀, 슬라이더 진행 방향 축 → 타자 쪽에 빨간 실밥 고리, 커브 탑스핀, 체인지업 많이 기움, 스플리터 회전 적음). 실제 rpm × 0.11 로 그림(실제 속도는 60fps에서 거꾸로 돌거나 멈춰 보이는 착시). 타구·송구는 시뮬 스핀 벡터로 회전.
- 투구 중 공 화면 지름 최소 = 창 높이 1.2%(8~14px). 기본 포수 뒤 시점 1440×800 에선 이미 릴리스 14px → 그대로, 작은 창·어깨 시점에서만 커짐.
- 지나간 **뒤** 통과 지점 점: 빨강 고정 → **노랑 = 존 통과, 하늘색 = 볼** (사후 피드백).
- 스크린샷 도구 `node tools/qa/pitchview.mjs --tag=after --types=FB,SL,CB --crop` → `tools/qa/.out/pitch-*.png` (타자 시점, 공 화면 지름 표).

## 3. 안 한 것 / 제안
- 포수 미트 미리 대기: 실제론 투구 직전 미트를 코스에 둠 → 사실상 위치 미리보기라 **안 넣음**.
- 투구 중 궤적 꼬리(fx 트레일 40프레임, 후반 구종 색): 지나간 길만 보여 줘서 예측은 아니라 그대로 둠. 더 현실적으로 하려면 0.1초 잔상 + 흰색으로 줄이는 안(사용자 결정).
- 타자 카메라 위치·화각(포수 뒤 1.72m·25°): 실제 타자 눈(옆에서 봄)은 좌우 판단이 더 어려워서 안 바꿈.
- 마운드 높이·RELEASE(높이 1.85m, 17m) 같은 공통 값은 안 건드림.
